# Egypt Fashion Store (متجر الأزياء المصري)

## حزمة دمج مدار — مرحلة الحساب الأصلي

### حزمة التصميم التالية — الرئيسية والترويسة والفوتر فقط

حزمة `public/wordpress-storefront-stage.tar.gz` منفصلة عن حزمة الحساب. تنقل الهوية العاجية والصور المحلية والشريط المتحرك والبحث عن منتجات WooCommerce وعرض أحدث أربعة منتجات فعلية. رابط الحساب يستخدم إضافة الحساب السابقة، والـMini Cart هو بلوك WooCommerce الأصلي. لا تنقل واجهة المنتج أو الحساب الجديدة بالكامل، ولا تنقل lookbook أو المفضلة أو اختيار اللغة/البلد أو المشهد المثبت وأثر المؤشر. لا توصف بأنها نسخة مطابقة كاملة لكل React.

**تعليمات Antigravity لهذه الحزمة، بعد نجاح مرحلة الحساب:**

1. استهدف `capability-test` فقط، واحتفظ بتعديلات الحساب الحالية والخيارات والطلبات. لا تعدّل ملفات الإضافة أو قاعدة البيانات ضمن مرحلة التصميم. خذ نسخًا احتياطية جديدة مؤرخة بالثواني، ولا تستبدل النسخ السابقة. سجل HEAD وstatus؛ التعديلات المعتمدة من مرحلة الحساب متوقعة، ولا تعتبرها سببًا لحذفها أو عمل reset.
2. افحص diff للحزمة مقابل القالب المحلي واعرضه قبل التطبيق. قائمة النقل: `storefront.php`، `functions.php` (دمج فقط)، `theme.json` (قيم palette فقط)، `style.css` (متغيرات الألوان فقط)، `assets/storefront.css`، `assets/images/`، `templates/front-page.html`، `parts/header.html`، `parts/footer.html`. لا تنسخ مجلد القالب كاملًا. في functions الحالي أضف تحميل storefront.php ودالة enqueue الجديدة مرة واحدة، ولا تستبدل أي وظائف محلية أخرى. لا تنقل `storefront.source.css` كبديل للملف compiled؛ المصدر موجود للتطوير والملف compiled جاهز دون Node على جهاز العميل.
3. تحقق من تسجيل `madar_account_link` ووجود WooCommerce والقالب الأب. لا تثبّت إضافات جديدة. افحص PHP المعدل بـ php -l وJSON بواسطة parser، ثم تحقق أن CSS والصور تستجيب 200 من مسار القالب نفسه. لا تستخدم روابط الصور الخاصة بمعاينة Figma داخل WordPress.
4. قبل تغيير القوالب افحص wp_template وwp_template_part المحفوظة في Site Editor للرئيسية/header/footer. لو تغلبت قاعدة البيانات على الملفات، توقف واعرض القوالب المتأثرة واطلب موافقة خاصة لإجراء Reset لتلك التخصيصات فقط بعد تصديرها. لا تحذف جميع تخصيصات المحرر ولا تدّع أن نسخ الملفات سيغير العرض تلقائيًا.
5. لا تغيّر إعداد front page أو اسم الموقع أو slugs تلقائيًا. الروابط ديناميكية من WooCommerce. بطاقتا الرجال والأطفال تفتحان التشكيلة العامة مؤقتًا، لأن تصنيفات الأقسام الحالية لم تُعتمد؛ لا تنشئ تصنيفات أو تنقل المنتجات من عندك. سياسة الخصوصية تظهر فقط إذا كانت صفحة معتمدة محددة بالفعل.
6. اختبر أن الرئيسية الجديدة تعرض صور الرجال والأطفال والألوان العاجية والشريط المتحرك، وأن المرور عليه يوقف الحركة وprefers-reduced-motion يلغيها. اختبر البحث بنتيجة موجودة ونتيجة غير موجودة، وروابط الحساب والسلة، وفتح Mini Cart وتحديثه بعد الإضافة. المنتجات والأسعار والمخزون من WooCommerce وليست أسعار React الوهمية.
7. أعد اختبار الحساب الحالي والدخول والخروج وإنشاء طلب جديد عبر Checkout مع بريد محجوب للتأكد أن تحديث التصميم لم يكسر الوظائف. لا تعوض ذلك بطلب سابق. لا تغيّر بيانات الشحن أو الدفع أو المخزون يدويًا لتطابق قيمة متوقعة.
8. التقط full-page screenshots للرئيسية على 1440 و375px، ولقطات للترويسة والبحث والسلة والحساب. قِس clientWidth وscrollWidth للصفحات الأساسية. قدم روابط/صور فعلية قابلة للمراجعة لا مسارات جهازك فقط. إذا ظهرت مشكلة خارج قائمة النقل، سجلها وتوقف؛ لا تغير التصميم باجتهاد.
9. التسليم: diff كامل، حالة كل اختبار، معرف الطلب الجديد وcreated_via والإجمالي الفعلي، والقوالب المحفوظة التي احتاجت اعتمادًا. لا commit/push/merge ولا حذف عناصر الاختبار دون موافقة. لا تستخدم حزمة الحساب القديمة أو حزمة wordpress-handoff القديمة لاستبدال التصميم.

التنسيقات الجديدة مولدة من Tailwind utilities ذات prefix `madar`، بدون CSS reset، لتقليل التعارض مع WooCommerce والقالب الأب. الخطوط من Google Fonts تحتاج اتصالًا؛ صور الحملة محلية ولا تمثل بالضرورة نفس منتجات المخزون. الحزمة تحتاج اختبار WordPress محلي فعلي؛ معاينة React هنا لا تعرض هذه القوالب PHP.

تمت مراجعة الفرع البعيد `feature/madar-storefront` عند `59c88053f9390f01687f58ada62b8f5e3e846327`. ملف الإضافة الرئيسي هنا يطابق ذلك الفرع قبل إضافة تحميل `account.php`. بقية ملفات القالب في هذه الحزمة قديمة مقارنة بالفرع؛ **لا تنقل الحزمة كاملة فوق القالب الحالي**. هذه المرحلة لا تنقل توسعات React أو أنيميشنزها إلى WordPress، ولا تنشئ نظام مصادقة أو API مخصصًا؛ تعتمد على نظام WordPress وWooCommerce الأصلي.

### تعليمات تنفيذ صارمة لـ Antigravity — الحساب فقط

1. **الفحص أولًا:** المستهدف الوحيد `capability-test`. اعرض المسار الحقيقي، `siteurl`، نوع البيئة، حالة القالب والإضافات، الفرع وHEAD و`git status --short`. لا تستنتج نجاح أمر من مجرد تشغيله. لا تستخدم `--skip-plugins=local-email-guard`؛ ذلك لا يتجاوز MU plugins أصلًا. لا تطبع `wp-config.php` أو الأسرار أو الكوكيز أو محتوى سجلات البريد.
2. **شروط توقف:** إذا كان الموقع ليس محليًا، أو غير شغال، أو الفرع مختلفًا، أو توجد تعديلات غير محفوظة في ملفات الهدف، توقف وبلّغ المستخدم. إذا تغير HEAD عن المعرف أعلاه، اعرض الفروقات ذات الصلة واطلب اعتمادها قبل التطبيق. لا تعمل checkout/reset/stash/clean/force تلقائيًا. لا تلمس `v1` أو `capability-test-restored`.
3. **نسخة احتياطية:** خذ ملفات وقاعدة بيانات قبل التعديل بأسماء مؤرخة لا تستبدل نسخًا سابقة. تحقق من exit code، قابلية قراءة الأرشيف، وعدد ملفات النسخة. استخدم ملف SQL مباشرًا بترميز utf8mb4؛ لا تمرره عبر PowerShell pipeline قد يغير الترميز. لا تدّع نجاح الاستعادة دون استعادة فعلية.
4. **قائمة الملفات المسموح تغييرها:** انسخ `plugins/egypt-fashion-core/account.php` و`verify-account.php` فقط إلى نفس مجلد الإضافة المحلية. في الملف الرئيسي الحالي أضف `require_once __DIR__ . '/account.php';` مرة واحدة بعد حارس ABSPATH أو في نهاية الملف. لا تستبدل الملف الرئيسي كاملًا إذا اختلف عن نسختنا. في `parts/header.html` الحالي أضف بلوك shortcode `[madar_account_link]` بجوار mini-cart، مع الحفاظ على جميع روابط التنقل الحالية. لا تنسخ header الموجود في الحزمة فوق header المحلي لأنه أقدم. اعرض diff قبل التفعيل.
5. **الإعدادات المسموح بها:** سجّل قيم الخيارات السابقة أولًا. لا تغيّر `users_can_register`؛ تسجيل WooCommerce منفصل عنه. تأكد أن `default_role` هو `subscriber`؛ إذا اختلف توقف واطلب مراجعة بدل تغيير الدور بصمت. فعّل `woocommerce_enable_myaccount_registration=yes` و`woocommerce_registration_generate_password=no` و`woocommerce_enable_checkout_login_reminder=yes` و`woocommerce_enable_signup_and_login_from_checkout=yes`. كلمة المرور التي يختارها المستخدم تُخزن وتتحقق عبر WordPress، ولا تكتب نظامًا بديلًا. إعداد كلمة المرور هذا لتسهيل الاختبار المحلي مع البريد المحجوب؛ لا تعتمد إعدادات الإنتاج دون مراجعة.
6. **صفحة الحساب:** اقرأ `woocommerce_myaccount_page_id` وتحقق أن الصفحة منشورة وفيها `[woocommerce_my_account]`. لا تستبدل محتوى الصفحة أو تحذف أي Blocks موجودة. إذا كانت مفقودة أو تستخدم قالبًا آخر، اطلب اعتماد إصلاحها أولًا. احترم أي header محفوظ في Site Editor؛ إن كان يتغلب على الملف، بلّغ واطلب اعتماد إدراج الرابط فيه دون حذف التخصيصات. لا تغيّر slugs ولا اسم الموقع ولا permalinks إلا عند مشكلة مثبتة واعتماد منفصل.
7. **تشغيل الأدوات:** افتح Site shell من Local واستخدم مسارات PHP وWP-CLI الفعلية التي اكتشفتها، لا تخمّنها من سجل قديم. افحص الملفات الثلاثة المعدلة بـ `php -l`. نفّذ خيارات الإعداد فقط باستخدام `wp option update` بعد تحقق المسار. إذا WP-CLI فشل لا تنشئ bypass للمصادقة ولا تعدّل جداول المستخدمين مباشرة؛ أوقف المهمة واعرض الخطأ المنقح.
8. **البريد:** تحقق من حارس البريد المحلي وفعاليته باختبار إلى عنوان `example.com`، مع منع الإرسال الخارجي. لا تعتبر وجود الملف دليلًا كافيًا. محتوى reset يحتوي سرًا؛ افحصه محليًا فقط، ولا تضع الرابط أو التوكن أو كلمة المرور في screenshot أو تقرير أو Git. لا تعطّل الحارس لحل مشكلة إنشاء الحساب.
9. **اختبار متصفح جديد:** سجل عميلين A وB من نموذج الحساب نفسه، ببيانات وهمية وبريدين `example.com` مختلفين وكلمات مرور لا تظهر في التقارير. تأكد من الدور `customer` لا Administrator ولا Shop Manager. اختبر البريد المكرر، الدخول الخاطئ، الدخول الصحيح، الخروج، واستمرار الجلسة مع تحديث الصفحة. لا تولّد كوكي مشرف بالـPHP ولا تستخدم Application Password كبديل لتسجيل دخول العميل. اختبر العنوان وتعديل بيانات الحساب وتغيير كلمة المرور عبر النماذج الأصلية.
10. **استرجاع كلمة المرور:** اطلب reset من النموذج الأصلي، وافتح الرسالة المحجوبة محليًا، ثم أكمل reset. تحقق من رفض كلمة المرور القديمة وقبول الجديدة، ومن رفض إعادة استخدام رابط reset. لا تعدل password مباشرة باستخدام WP-CLI لتجعل الاختبار ينجح. إذا الحارس لا يسمح بمعاينة الرسالة، سجّل الاختبار BLOCKED واطلب تعديلًا منفصلًا للحارس؛ لا تدّع PASS.
11. **طلبات مملوكة فعليًا:** في جلسة A نفسها، أضف منتجًا متاحًا إلى السلة، أكمل Checkout ببيانات وهمية وCOD وبريد محجوب. أنشئ طلبًا جديدًا لـB من جلسة مستقلة كذلك. لا تعوض ذلك بطلب قديم أو `wc_create_order`. تحقق من أن كل طلب `created_via=checkout` وصاحبه صحيح وتاريخه أحدث من بدء المهمة. سجّل القيم الفعلية للمنتجات والشحن والإجمالي، لا تفرض 500 إذا اختلف المنتج أو الشحن. لا تُنشئ صلاحية يدوية للوصول إلى الطلب.
12. **فحص الصلاحيات البرمجي للقراءة فقط:** ضع IDs العميلين في متغيري بيئة `MADAR_TEST_CUSTOMER_A` و`MADAR_TEST_CUSTOMER_B` ثم شغل `wp --path=<verified-site-path> eval-file <verified-plugin-path>/verify-account.php`. السكربت لا ينشئ حسابات أو طلبات ولا يغير المخزون؛ يفشل إذا لم توجد الطلبات اللازمة. لا تعدّل assertions لإجباره على النجاح. يتطلب WP_ENVIRONMENT_TYPE محليًا/development/staging؛ إذا غير مضبوط لا تتجاوز الحارس، اطلب اعتماد ضبطه.
13. **اختبار HTTP للصلاحيات:** A يرى طلبه فقط؛ فتح رابط view-order الخاص بـB من جلسة A يجب ألا يعرض المنتجات أو العنوان أو الهاتف أو الإجمالي الخاص بـB. كرر العكس ثم كزائر. قد يكون الرفض رسالة WooCommerce وليس HTTP 403؛ افحص غياب البيانات لا الكود فقط. اختبر وصول العميل إلى wp-admin وإدارة WooCommerce، ورفض طلب تعديل بيانات حساب دون nonce صالح. لا تكتف بإخفاء زر في الواجهة. لا تفتح REST admin endpoints أو تغير capabilities لتسهيل الاختبار.
14. **موبايل وأدلة:** التقط صفحة الحساب logged-out وlogged-in والطلبات والعناوين ونموذج Checkout بسلة ممتلئة باستخدام full-page capture الحقيقي على 375px. قِس documentElement.clientWidth وscrollWidth؛ افحص القصّ والكيبورد والتركيز. اخفِ بيانات الدخول وأسرار reset وorder keys. التقط نسخة desktop أيضًا. لا تغير ارتفاع النافذة فقط وتسمّي الصورة full-page.
15. **التسليم والتوقف:** اعرض ملفات التعديل وdiff، الخيارات قبل/بعد، PHP lint، نتيجة فحص الصلاحيات، ومعرفي الطلبين وتاريخيهما وcreated_via وصاحبيهما والإجماليات. صنف كل اختبار PASS/FAIL/BLOCKED/NOT TESTED بالأدلة؛ لا تستخدم «جاهز 100%». حصر حسابات وطلبات الاختبار وطريقة تنظيفها مع استعادة المخزون عبر WooCommerce؛ لا تحذفها دون موافقة. لا تعمل commit أو push أو merge أو تثبت إضافات جديدة أو تعدّل التصميم والضرائب والشحن والدفع. إذا ظهر عائق خارج قائمة العمل، توقف واطلب اعتماد خطوة منفصلة.

### حدود هذه المرحلة

`verify-account.php` يفحص صلاحيات WooCommerce ولا يثبت نجاح HTTP أو تسجيل الدخول أو reset وحده. لا توجد بيئة WordPress أو قاعدة بيانات العميل هنا؛ الاختبارات الحية تنتظر التنفيذ المحلي. لا نتعامل مع order-received public links أو endpoint view-order كأنهما نفس آلية الوصول؛ روابط تأكيد الطلب لها order keys خاصة يجب عدم نشرها. حماية الإنتاج (HTTPS، rate limiting، سياسة بريد حقيقية، جلسات ونسخ احتياطية) ليست معتمدة بمجرد نجاح هذه المرحلة المحلية.

هذه نسخة كود للتسليم وليست موقعًا تم تشغيله داخل WordPress هنا. تطبيق React في مشروع المعاينة مستقل؛ لا تنسخ ملفات React داخل الثيم. هذه الحزمة تقدم رئيسية بلوكات لثيم Twenty Twenty-Five، ومنتجات WooCommerce فعلية، وسلة Mini Cart أصلية. صفحة المنتج والسلة وإتمام الطلب تستخدم وظائف WooCommerce والقالب الأب، وليست نسخة مطابقة لكل تفاصيل معاينة React. البحث والمفضلة التجريبيان في React غير منقولين هنا. لا توجد بوابة دفع أو نشرة بريدية في الحزمة.

### تعليمات Antigravity للدمج المحلي

1. تحقق من الفرع والـcommit الحاليين. إذا تغيّرت نفس الملفات بعد 91d8c3b، راجع الفرق وادمج يدويًا؛ لا تستبدل تغييرات أحدث. لا تستخدم force push.
2. خذ نسخة جديدة من الملفات وقاعدة البيانات قبل التركيب. لا تعدّل v1 أو موقع الاستعادة. راجع ملفات هذه الحزمة قبل نقلها إلى capability-test.
3. تأكد من تثبيت القالب الأب: `wp theme install twentytwentyfive` إذا لم يكن مثبتًا. ثم انسخ مجلدي الثيم والإضافة إلى wp-content، وفعّل كلًا منهما بعد موافقة المستخدم. WooCommerce يبقى مثبتًا منفصلًا.
4. الرئيسية الجديدة في templates/front-page.html. النصوص والصورة قابلة للتعديل من المظهر ← المحرر. عنوان الموقع يأتي من إعدادات WordPress؛ لا تغيّره تلقائيًا إلى مدار. اضبط قائمة التنقل لتشمل المتجر والحساب والصفحات المعتمدة. راجع قالب الرئيسية المعروض فعليًا؛ القوالب المحفوظة سابقًا في قاعدة البيانات قد تتغلب على ملفات الثيم. لا تحذف تخصيصاتها دون موافقة.
5. استبدل صورة Unsplash بصورة في مكتبة الوسائط، أو اعتمد استخدامها وحقوقها. المنتجات والأسعار والصور تأتي من قاعدة WooCommerce الحالية، لا من منتجات React الوهمية. صورة الحملة لا تمثل مواصفات منتج فعلي. اعتمد أي ادعاءات شحن وهوية قبل الإطلاق.
6. أبق حجب البريد فعالًا محليًا، واحمِ السجلات من الوصول العام. لا تنقل الحارس للإنتاج دون خطة إرسال بريد فعلية.
7. اختبر الرئيسية والمنتج والـMini Cart والسلة وإتمام الطلب على سطح المكتب وموبايل 375px. اختبر روابط القائمة والكيبورد وعدم وجود تجاوز أفقي.
8. اختبر هاتف 01012345678 و+201012345678 و00201012345678 والأرقام العربية المكافئة. ارفض الحروف، والطول الخاطئ، والبادئات غير المدعومة. تحقق من الرقم المحفوظ في الطلب. تكامل Store API مضاف لكنه لم يختبر في هذه البيئة؛ اختبر Classic Checkout وCheckout Blocks كلًا على حدة. تخصيص عناوين الحقول يخص Classic فقط.

### التراجع والنشر

للتراجع، أعد ملفات الثيم والإضافة السابقة، أو أعد تفعيل القالب السابق وألغ تفعيل الإضافة المخصصة. تغييرات قاعدة البيانات تحتاج النسخة المناسبة؛ فك أرشيف فوق ملفات جديدة وحده ليس استعادة كاملة. لا تستورد قاعدة قديمة فوق متجر إنتاج لديه طلبات جديدة.

بعد نجاح الاختبار المحلي: جهز Staging منفصلًا مع HTTPS ومصادقة آمنة ومنع الفهرسة والبريد الحقيقي. اختبر النسخ والاستعادة والشحن والدفع في sandbox. قبل الإنتاج اعتمد بيانات العميل والضرائب والسياسات والمخزون والأسعار والشحن والدفع، وراقب البريد والطلبات. لا تنشر تلقائيًا، ولا تفترض معدل ضريبة موحدًا. القرارات الضريبية تعتمد على المحاسب وبيانات المنتجات.

مستودع الكود المخصص لمشروع متجر أزياء إلكتروني مصري مبني على **WordPress** و **WooCommerce**.  
يحتوي هذا المستودع حصريًا على الكود البرمجي المخصص (Custom Theme & Custom Core Plugin)، مع عزل تام لملفات نواة ووردبريس والإضافات الخارجية وقواعد البيانات.

## 3. خطوات التثبيت والتشغيل المحلي (Local Setup)

### الخطوة 1: استنساخ المستودع (Clone)
قم باستنساخ هذا المستودع في مجلد العمل الخاص بك:
```bash
git clone https://github.com/itachi-void/egypt-fashion-store.git
```

### الخطوة 2: ربط الكود بموقع ووردبريس المحلي
انسخ أو أنشئ روابط رمزية (Symlinks) لمجلدات الكود داخل مجلد `wp-content` بموقعك:
* انسخ `themes/egypt-fashion-child` إلى `wp-content/themes/`
* انسخ `plugins/egypt-fashion-core` إلى `wp-content/plugins/`

### الخطوة 3: تثبيت وتفعيل WooCommerce والإضافات الرسمية
لا يتم تضمين كود WooCommerce في هذا المستودع لكونه إضافة مفتوحة المصدر يتم تحديثها رسميًا. لتثبيتها عبر WP-CLI:
```bash
wp plugin install woocommerce --activate
```

### الخطوة 4: تفعيل القالب الفرعي وإضافة المتجر
```bash
wp theme activate egypt-fashion-child
wp plugin activate egypt-fashion-core
```

## 4. تنبيه هام بشأن قاعدة البيانات وبيانات WooCommerce

> [!IMPORTANT]
> **إعدادات ووكومرس، تصنيفات المنتجات، المنتجات، خيارات الشحن، والطلبات محفوظة بالكامل في قاعدة البيانات (MySQL Database) ولا تنتقل تلقائيًا عبر Git.**
> * **Git يتتبع:** ملفات الكود فقط (CSS, PHP, JS, Assets).
> * **قاعدة البيانات تحفظ:** بيانات المنتجات، إعدادات بوابات الدفع، سجلات الطلبات، وأسعار الشحن.
> * لنقل الإعدادات بين بيئة التطوير (Local) وبيئة المراجعة (Staging)، استخدم عمليات تصدير/استيراد قاعدة البيانات عبر WP-CLI أو أدوات ترحيل قواعد البيانات المعتمدة:
>   ```bash
>   # تصدير قاعدة البيانات محليًا
>   wp db export store-backup.sql
>   
>   # استيرادها على البيئة التجريبية (مع تحديث النطاق)
>   wp db import store-backup.sql
>   wp search-replace "http://store.local" "https://staging.store.com"
>   ```
